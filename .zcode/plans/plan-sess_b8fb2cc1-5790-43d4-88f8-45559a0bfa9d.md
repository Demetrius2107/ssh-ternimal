# P0 + 快速 P1 修复计划

经代码核实，原列表中的"跳板机 30s 超时切断"是**误报**（跳板目标 conn 是 SSH 通道连接，从未设置 30s deadline），予以跳过。本批修复以下 8 项正确性关键 bug，按原优先级顺序执行：

---

## P0-1：pump/output channel 生命周期（goroutine 泄漏）— 最严重

**根因**：`sshcore.Close()`/`telnetcore.Close()` 都不关闭 `output` channel，导致 `app.go:attachSession` 的 `for range sess.Output()` 永久阻塞，每次关闭/重连泄漏一个 goroutine。pump 在缓冲满时也会阻塞写。

**修复 `internal/sshcore/session.go`**：
- Session 结构体新增 `pumpWg sync.WaitGroup`
- `connectOnce`：启动两个 pump 前 `s.pumpWg.Add(2)`
- `pump`：`defer s.pumpWg.Done()`；写 channel 改为 `select { case s.output <- ...: case <-s.stop: return }`
- `Close()`：在 `closeOnce.Do` 内，关闭 stop/session/client/jumpClient 之后，`s.pumpWg.Wait()` 等待两个 pump 退出，再 `close(s.output)`。pump 因 conn 关闭后 `r.Read` 出错而退出，select+stop 保证不阻塞写

**修复 `internal/telnetcore/session.go`**：
- Session 结构体新增 `stop chan struct{}` 和 `pumpWg sync.WaitGroup`；Connect 初始化 `stop: make(chan struct{})`
- `pump`：`defer s.pumpWg.Done()`；写 channel 改 select+stop；**移除 pump 末尾的 `s.Close()` 自调用**（改为只发 done 信号后 return，避免 WaitGroup 死锁）
- `Close()`：`closeOnce.Do` 内 `close(s.stop)` → `s.conn.Close()` → `s.pumpWg.Wait()` → `close(s.output)`

**修复 `app.go:attachSession`**：
- Done goroutine 在清理前调用 `sess.Close()`（对 ssh 幂等，对 telnet 是主关闭路径），确保 output channel 被关闭、Output 消费 goroutine 退出

---

## P0-2：Exec 持全局锁阻塞终端输入

**根因**：`sshcore.Exec`（session.go:404-417）全程持 `s.mu`，`CombinedOutput` 网络阻塞期间 `Send`/`Resize`/`Close` 全部被阻塞。资源监控每 2s 调一次 Exec，周期性卡住键盘输入。

**修复 `internal/sshcore/session.go:Exec`**：仅在检查 `closed` 时短暂持锁，`NewSession`+`CombinedOutput` 在锁外执行。`s.client` 构造后不变，关闭后 NewSession 会返回错误，安全。

---

## P0-3：保存会话丢失跳板机/私钥/OTP 字段（前后端联动）

**根因**：`StoredSession` 模型缺字段；`SaveSession` 13 个位置参数不含这些字段；`LoadSession` 不回填；前端 `loadSelected` 不 set 这些字段。

**修复 `internal/model/model.go:StoredSession`**，新增字段：
- `Protocol`、`PrivateKeyPath`、`OTP`
- `JumpHost`、`JumpPort`、`JumpUser`、`JumpPrivateKeyPath`

**修复 `app.go:SaveSession`**：改签名为 `SaveSession(cfg model.SshConfig, name, group, tags string) (string, error)`，从 cfg 提取所有字段构造 StoredSession；密码类敏感值入 keyring（password→`id`，proxyPassword→`id:proxy`，jumpPassword→`id:jump`，passphrase→`id:pass`，jumpPassphrase→`id:jumppass`）

**修复 `app.go:LoadSession`**：从 StoredSession + keyring 还原完整 SshConfig（含跳板/私钥路径/passphrase/OTP/protocol）

**重新生成 wails 绑定**：运行 `wails generate module` 更新 `frontend/wailsjs/`

**修复 `frontend/src/ConnectForm.tsx`**：
- `saveSession` 调用改用新签名，传入完整 cfg + name/group/tags
- `loadSelected` 回填 `protocol/authMethod/keyPath/passphrase/otp/useJump/jumpHost/jumpPort/jumpUser/jumpPassword`

**修复 Vault 导出/导入**（`app.go` vaultSession）：同步补 jumpPassword/jumpPassphrase 字段，保持导入导出一致

## P0-4：非激活会话输出 + ai-explain 事件串扰

**根因 A**：`AiDelta` 结构体无 sessionId，`AiExplain` 的 4 个 emit 全局广播，所有 TerminalView 实例都追加 explainText。
**根因 B**：非激活会话的 TerminalView 仍持续 term.write，无节流。

**修复 `internal/model/model.go`**：`AiDelta` 增加 `SessionID uint64 json:"sessionId"`

**修复 `app.go:AiExplain`**：4 个 emit 点（delta/error×2/done）payload 带 `SessionID: sessionID`；`AiChat` 的 emit 带 `SessionID: 0`（AiPanel 不过滤）

**修复 `frontend/src/TerminalView.tsx`**：
- 新增 `activeRef`，`useEffect([active])` 同步 `activeRef.current = active`
- `onOutput`：active 时正常 flush；非 active 时仍累积到 pendingRef（不丢数据），但跳过 term.write 渲染；变 active 时触发一次 flush。pendingRef 上限 512KB（超限丢弃前段）
- ai-explain-delta/done/error 订阅：加 `if (e.sessionId !== sessionId) return`

## P1-1：审计补记误覆盖其他会话

**根因**：`startAudit` 丢弃 `SaveAudit` 返回的 ID；`updateAuditEntry` 按"第一条未完结"匹配，多并发会话会误覆盖。

**修复 `app.go`**：
- App 结构体新增 `auditIDs map[uint64]string`，`startup` 初始化
- `startAudit`：捕获 `SaveAudit` 返回 ID 存入 `a.auditIDs[id]`
- `finishAudit`：从 `auditIDs` 取 ID，构造带 ID 的 AuditEntry 直接 `SaveAudit`（按 ID 覆盖），删除 `updateAuditEntry` 的遍历匹配逻辑

---

## P1-2：AI 脱敏 mask 键名错位

**根因**：`Sanitize` 用 `ReplaceAllString(out, s.mask(out, re))`，mask 只取第一个匹配的子组生成替换串，用于替换所有匹配，导致第 2+ 个匹配的键名被第一个的键名覆盖（值仍脱敏，非安全漏洞）。

**修复 `internal/ai/sanitize.go:Sanitize`**：改用 `re.ReplaceAllStringFunc(out, func(match string) string {...})`，在回调内对每个匹配独立调用 `re.FindStringSubmatch(match)` 生成正确替换串。

---

## P1-3：VncPanel 按键事件重复发送

**根因**：`VncPanel.tsx` 的 `onKeyDown` 和 `onKeyUp` 复用同一 `onKey`，函数内同时发 down+up，每次按键发 4 个事件。

**修复 `frontend/src/VncPanel.tsx`**：拆分为 `onKeyDown`（发 keydown）和 `onKeyUp`（发 keyup），分别只发对应事件。

---

## P1-4：LogPanel 检索计数读旧 state

**根因**：`LogPanel.tsx:doSearch` 在 `setMatches(...)` 后立即用闭包旧 `matches` 判断，首次搜索总显示"无命中"。

**修复 `frontend/src/LogPanel.tsx:doSearch`**：基于 `SearchHistory` 的返回值判断，而非闭包 state。
