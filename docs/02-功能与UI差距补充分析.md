# ssh-terminal 功能与 UI 差距补充分析

> 分析日期：2026-08-15
> 对标对象：① Termius 官网 https://termius.com + 官方文档 https://docs.termius.com（商业标杆）
> ② termius-plus 开源项目 https://github.com/2211898719/termius-plus（94★，模仿 Termius 的 Web 运维工具，Spring Boot + Vue）
> 结论用途：确认当前项目与两大对标的功能/UI 缺失，形成后续开发优先级依据。

---

## 1. 对标对象概况

### 1.1 Termius（商业产品，200 万+工程师使用）

- **形态**：跨平台桌面 + 移动端（macOS / Windows / Linux / iOS / iPadOS / Android），云同步
- **核心模型**：Vault（端到端加密存储）→ Groups（嵌套分组，共享设置继承）→ Hosts（一台机器多协议）
- **关键功能**：
  - Vaults：个人/团队保险库，端到端加密同步所有数据（主机、密钥、片段、端口转发规则、Known Hosts）
  - Keychain：集中管理凭据（用户名/密码/SSH 密钥/证书/Identities），多主机引用不重复
  - Hosts：多协议（SSH / Mosh / SFTP / Telnet），标签搜索、跳板/代理设置
  - Workspaces：多会话分组，Focus/Split 视图、广播命令、模板化保存恢复
  - Snippets：命令片段侧栏运行、自动补全触发、多主机批量执行
  - Autocomplete：IDE 风格（片段、shell 历史、路径、命令参数、sudo 密码）
  - AI in terminal：自然语言描述 → shell 命令生成（回车下箭头触发）
  - Session logs：自动采集会话日志、跨设备同步、团队共享、搜索、书签
  - SSH ID（Passkeys）、端口转发、SFTP、AWS/Azure/DO 集成、SAML SSO、后量子加密

### 1.2 termius-plus（开源 Web 运维工具）

- **形态**：Spring Boot + Vue（ant-design-vue）+ MySQL + Redis，Web 端 xterm.js + monaco-editor，sshj 协议库
- **关键功能**：
  - 服务器组列表 + 终端 + SFTP + 端口转发（动态）
  - 编辑器（monaco-editor，AI 补全、语法高亮、格式化）+ 分屏拖拽服务器对服务器传文件
  - 权限管理（RBAC 角色授权、多用户）
  - 自定义命令片段、每服务器独立文档、内置 Linux 命令速查
  - 自定义代理（组级代理就近使用）
  - 应用管理：信息 / 身份凭据 / 端点监控（正则判异常 + 钉钉通知）/ 服务器架构图
  - 定时任务（cron + mvel 脚本 + 钉钉通知）、操作日志（缓存+文件审计）

## 2. 功能差距比对（当前项目 vs 两大对标）

图例：✅ 已实现  🟡 部分实现  ❌ 未实现

### 2.1 对标 Termius

| Termius 功能 | 当前项目 | 差距说明 |
|---|---|---|
| SSH 终端 | ✅ | 密码/私钥/OTP、PTY、多标签、搜索、keepalive |
| Telnet | ✅ | 已支持 |
| SFTP 文件管理 | ✅ | 双栏、目录传输、冲突策略、大小校验 |

| Keychain 集中凭据 | ❌ | 密码仅按会话存系统凭据库，**无"身份/凭据引用"模型** |

| 云服务集成 | ❌ | 无（AWS/Azure 等） |
| 移动端 | ❌ | 无（可选） |

## 3. UI 差距分析

### 3.1 布局结构

| 维度 | Termius | termius-plus | 当前项目 | 差距 |
|---|---|---|---|---|
| 导航 | 左侧栏 Vaults→Groups→Hosts 树 + 搜索 | 服务器分组侧栏 | 首页快速连接 + 顶部工具栏 | ❌ 无会话树/分组树，无全局搜索 |
| 连接入口 | 主机详情面板（凭据/端口/连接） | 组列表点选 | 表单填写 | 🟡 可保存会话，但无分组折叠 |
| 终端区 | 多标签 + 分屏 + Focus 模式 | 多标签 + 分屏 | 多标签 | ❌ 无分屏 |
| 侧边栏 | 片段/历史/主题面板 | 文件/编辑器面板 | 无 | ❌ 无侧边辅助面板 |

### 3.2 视觉设计语言

| 维度 | Termius | 当前项目 | 差距 |
|---|---|---|---|
| 风格 | 现代扁平 + 深色为主，卡片式主机列表 | 深度玻璃化（Liquid Glass）+ Apple 风格 | ✅ 已确认走玻璃化路线，方向契合 |
| 主题 | 官方主题 + 自定义 | 6 套主题 | 🟡 可扩展自定义/导入导出 |
| 主机展示 | 带标签/状态的卡片列表 | 会话列表 | 🟡 缺标签/状态徽标 |
| 状态反馈 | 连接状态、活动指示 | 网络状态栏 + 保活 RTT | ✅ 已有 |

## 4. 缺失项分级与建议优先级

### P0（个人工具核心体验，强烈建议尽快）

1. **GBK 编码支持** — 连 Windows 服务器中文乱码，分析文档已标记"必须优先解决"
2. **known_hosts 指纹校验** — 安全缺口，改动小
3. **分组 Groups** — 会话树/分组/标签，直击"会话一多就乱"的痛点（对标 Termius 最核心模型）
4. **远程编辑** — 补齐 SFTP 工作流闭环（对标 termius-plus 编辑器）

### P1（拉开差距的功能）

5. **AI 集成（M5）** — DeepSeek + 上下文注入 + 脱敏 + 成本控制，选型文档差异化核心
6. **Snippets 命令片段** — 对标双产品都有
7. **日志面板**（搜索/回放）— 现有落盘数据未利用
8. **分屏** — Workspaces 的第一步

### P2（扩展/长期）

9. **HTTP/SOCKS 代理连接**、云同步 Vault、Passkeys、监控告警、定时任务、RBAC、云服务集成、移动端

---

## 5. 结论

1. **功能定位差异**：Termius 是"个人+团队基础设施访问管理"（模型化：Vault/Groups/Host），termius-plus 是"团队 Web 运维平台"（RBAC/监控/定时任务/审计）。当前项目介于两者之间：**终端/SFTP/隧道等连通性功能已很扎实，缺的是"管理模型层"（分组、凭据集中、片段、日志面板）和"AI 差异化层"**。
2. **UI 差距**：主要是**缺左侧会话树 + 分屏 + 侧边面板**；视觉语言（深度玻璃化）已确认方向且已落地，无需推翻。
3. **建议路线**：P0 的 4 项（GBK → known_hosts → 分组 → 远程编辑）补齐个人工具完整性；随后上 P1 的 AI 集成作为差异化卖点。分组（Groups）是承上启下的关键——它同时是日志面板、片段、AI 上下文的组织基础。

> 注：termius-plus 采用 GPL 兼容的 Mulan PSL-2.0 开源协议，可参考其设计思路与交互，但本项目为 Wails+Go 自研，代码不直接复用。
