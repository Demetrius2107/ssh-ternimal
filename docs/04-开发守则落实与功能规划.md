## 1. 开发守则落实（自检清单，今后每次开发/提交执行）

### 1.1 Git 提交规范（用户硬性要求）

- [x] **提交信息不带 atomcode 字样**：无 `Co-Authored-By: AtomCode` 尾注，主题/正文不提及（从本文档提交起严格执行）
- [ ] **最小提交**：一次 commit 只做一件完整的事，按功能点拆分，绝不做大杂烩提交
- [ ] 提交前 `git status` 检查暂存范围，只 add 本功能涉及的文件，提交后工作区干净
- [ ] Conventional Commits 前缀（feat/fix/docs/refactor/chore/build），自然语言中文

### 1.2 业务分析纪律（自动生效）

- [ ] 涉及业务逻辑的开发任务，**先做业务分析再写代码**（本文件第 3 节为规划中功能的预分析）
- [ ] 分级：核心业务设计（完整 5 阶段）/ 一般功能（业务规则 + 关键异常分支）/ 简单修复（直接执行）
- [ ] 命名体现业务语义（领域统一语言），禁止 UserDAO/getUserById 式技术命名
- [ ] 每个正常流程至少考虑 1 个异常分支；并发场景考虑幂等/锁/一致性
- [ ] 测试按业务场景命名（如"保存会话后加载应返回原配置"），非仅代码路径
- [ ] 未经验证的大厂架构/行业实践不引用

### 1.3 开发纪律

- [ ] 改完必须验证（go build / go test / tsc），验证用快速检查，不启动长驻进程
- [ ] 不做超出任务范围的额外改动
- [ ] 破坏性操作（删除/改历史）前先确认

## 3. 后续功能规划（按业务分析纪律预分析）

### P0 — 守则落实与技术债（先做）

#### 3.1 测试命名整改 + 缺失测试补全
- **级别**：L3（简单修复）+ L2
- **业务规则**：测试名体现业务场景而非代码路径；核心包（vnccore/vault/ai 限额逻辑）补单测
- **异常分支**：VNC 握手失败/认证失败、Vault 密码错误/数据篡改（已有，补用例）
- **命名示例**：`TestSaveSessionThenLoadReturnsOriginalConfig` 替换 `TestSessionCRUD`

#### 3.2 终端渲染性能优化（超大日志不卡顿）
- **级别**：L2
- **业务规则**：大输出（tail 日志）不阻塞 UI；滚动缓冲上限；输出节流
- **异常分支**：超大单帧输出（>缓冲上限）截断不丢尾部关键信息
- **命名**：`当tail千行日志时应流畅滚动不卡顿`

### P1 — 差异化深挖（内网运维 + 审计方向）

#### 3.3 会话审计录屏（Teleport 式）
- **级别**：L2（安全合规场景）
- **业务规则**：审计不仅记录元数据，还**按时间轴录制终端输出**（可回放完整操作过程）；录制需加密存储；支持导出
- **异常分支**：录制文件损坏/超限；审计回放与实时输出不一致
- **数据模型**：AuditEntry 扩展 `RecordingPath`；回放复用现有 LogPanel 时间轴
- **命名**：`录制会话后回放应逐字符还原`

#### 3.4 凭据集中管理 Keychain（Termius 式身份引用）
- **级别**：L1（有状态与共享语义）
- **业务规则**：凭据（密码/密钥/代理认证）集中存储，**多个会话引用同一身份，一处修改全局生效**；引用关系持久化；凭据仅在系统凭据库加密存储
- **异常分支**：被引用凭据删除时引用方处理（标记失效/阻止删除）；凭据修改后已建立会话不受影响
- **状态机**：凭据（活动/失效）；引用（有效/悬空）
- **命名**：`修改凭据后所有引用会话应使用新值`、`删除被引用凭据应阻止`

#### 3.5 脚本化/宏（SecureCRT/MobaXterm 式）
- **级别**：L2
- **业务规则**：片段支持变量占位（`{host}`/`{user}`/`{date}`）与顺序执行（宏）；执行前变量求值；结果反馈
- **异常分支**：变量未定义时提示并中止；宏中途失败停止后续
- **命名**：`片段含未定义变量时执行应中止并提示`

#### 3.6 内网穿透/SSH 加速（FinalShell 式，可选）
- **级别**：L1（网络协议 + 安全）
- **业务规则**：经公网中转连接内网主机（注册/隧道建连/加密）；访问需授权码
- **异常分支**：中转不可达、授权过期、多端冲突
- **安全**：全程 TLS + 端到端加密；中转服务不落明文
- **命名**：`内网主机经中转应可被授权端连接`

### P2 — 扩展与长期

#### 3.7 云同步后端服务（M7：账户 + 加密同步）
- **级别**：L1（完整 5 阶段：场景建模/规则/状态机/一致性/安全）
- **业务规则**：账户注册登录；Vault 加密数据（客户端已加密）同步到服务端；**服务端不可解密**（零知识）；多设备冲突策略（时间戳合并/手动选择）；设备撤销
- **异常分支**：断网重传、冲突、密码丢失（数据不可恢复需明示）
- **一致性**：同步幂等、last-write-wins + 冲突提示
- **安全合规**：口令 KDF（PBKDF2/Argon2）、会话令牌、审计登录
- **命名**：`同一会话在两台设备修改后应提示冲突`

#### 3.8 FreeRDP 内嵌（M4 V2 剩余）
- **级别**：L1（需引入 cgo 依赖或 WebSocket 渲染方案）
- **业务规则**：RDP 渲染进应用窗口；剪贴板/文件重定向；断线重连
- **异常分支**：凭据交互（CredSSP）、证书校验
- **风险**：cgo 编译复杂度高，评估 Guacamole WebSocket 方案替代

#### 3.9 端点监控告警（FinalShell 式）
- **级别**：L2
- **业务规则**：CPU/内存/磁盘阈值告警（正则+阈值）；通知渠道（系统通知/钉钉 webhook）
- **异常分支**：告警风暴抑制（同指标去重）；恢复通知
- **命名**：`CPU超过阈值应触发一次告警且不重复刷屏`

#### 3.10 定时任务（cron + 脚本，termius-plus 式）
- **级别**：L2
- **业务规则**：会话内定时执行命令/脚本；结果落盘与通知；表达式校验
- **异常分支**：会话断开任务处理（标记失败/重试）；表达式非法拒绝
- **命名**：`定时任务在会话断开时应标记失败`

## 4. 命名规范（领域统一语言对照）

| 禁止（技术术语） | 采用（业务语义） |
|---|---|
| UserDAO / getUserById | SessionRepository / findSessionByLabel |
| SaveSnippet / DeleteSnippet | 保留（片段是业务概念，可接受） |
| TestSessionCRUD | Test保存会话后加载应返回原配置 |
| vncSendData | vncSendKeyEvent / vncSendPointerEvent |

> 原则：**基础设施操作（网络/IO/渲染）可用技术命名；业务概念（会话/凭据/片段/审计/任务）必须业务语义命名。**
